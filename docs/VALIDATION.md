## 历史测试与当前限制

- 早期可执行诊断轮次完成过 CPU 名称、GPU 身份筛选、缺失传感器、额度轮换 / 过期等场景（一次扩展场景 182 项通过）。此后修改过单卡宽度、频率与单位对齐；**该历史结果不能代表最新代码完整回归**。
- 最新诊断探针此前被 Windows 应用程序控制阻止执行。保留拦截，不关闭安全功能，也不改名、换宿主绕过。因此新增场景只有编译验证，没有全套运行通过声明。
- 任务栏父窗口、样式与位置恢复曾通过检查，但后续鼠标命中探针出现 `childIsHitTarget=False`。这项未解决记录仍保留；用户实际可见 / 可交互的反馈不能自动抹去该诊断失败。
- 托盘箭头、截图遮罩、实际 Explorer 重启及跨屏 DPI 全套回归仍未完成。界面操作工具不可用；生产绘制的 PNG 不替代这些桌面交互验收。
- Kimi 仅有发现逻辑，真实账户额度尚未接通。单独发起官方客户端登录不等于完成 TaskbarTelemetry 集成或通过账户界面对照。
- 温度 / 频率依赖设备、驱动、权限与可选传感器后端。某个环境有数字，不能宣称所有 CPU 均支持，也不能等同独立仪器精度验证。

## 稳定运行包发布前

1. 从干净源码构建，完成当前版本的全部场景测试；若系统拦截，保留为未通过。
2. 人工确认 UAC、可见性与右键菜单；反复打开托盘箭头至少 30 秒，无消失或闪烁。
3. 截图遮罩保持至少 10 秒，工具不浮到其上；取消后继续更新。
4. 保存工作后重启 Explorer，确认重新挂载且仅一个实例。
5. 验证真实 100% / 150% / 200% DPI、深浅主题、单卡与双卡设备，以及无 NVIDIA / 无额度来源。
6. 新额度来源必须与真实账户页面的窗口、百分比和重置时间一致，才能升级支持声明。
7. 复查默认配置、隐私清理、第三方许可和 SHA-256；打包脚本必须在测试失败时停止。
